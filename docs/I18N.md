# Internationalization (i18n) Baseline

## Current Strategy
- UI language mode is configuration-driven via `config/settings.json`.
- Supported values:
  - `zh_en`: Chinese primary with English term hints (default)
  - `zh`: Chinese only
  - `en`: English only
- Runtime display is primarily handled by inline bilingual labels in `main.py`.

## Compatibility Notes
- `utils/i18n.py` is standardized on `PySide6` APIs.
- Legacy `PyQt5` translator code path is not used by the current `main.py` entrypoint.
- Existing `translations/malody_zh_CN.ts` and `.qm` are kept for packaging compatibility.

## Usage Contract
- Any new user-facing text should follow this rule:
  - Use `MainWindow._bi(zh, en)` for status/event text when possible.
  - In `zh_en` mode, render `中文 (English)`.
  - In `zh` or `en` mode, render a single language.

## Out of Scope (This Phase)
- No full text externalization for all GUI strings.
- No pluralization/ICU message format.
- No dynamic locale switch without reopening or refresh.
